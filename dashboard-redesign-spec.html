Dashboard Redesign

The admin dashboard, restyled to the app's design system and simplified for two admins. Three moves: 1) one-step sign-in (the access-code pre-gate goes away — the email allowlist + password already does that job), 2) de-chunked UI — boxed-and-bordered cards become hairline rows and one quiet stat strip, exactly like the app's stats surfaces, 3) Ryan (ryanjburke34@gmail.com) added as a first-class admin with his own credentials — no shared passwords.

Sign in — one step REPLACES CODE-GATE + LOGIN

Today you type an access code, then an email, then a password — three secrets across two screens. The redesign is one screen: email + password against the Supabase auth user, checked against the two-address allowlist. Fewer steps, same wall. Sessions last 30 days so you're not re-logging in weekly.

Why this is still secure

  • Allowlist is the gateonly your two emails pass ADMIN_EMAILS — a random visitor with the URL has no path in
  • Real credentials eachRyan gets his own Supabase auth user — revocable independently, no shared secret in iMessage
  • The access code added ≈0one static secret shared by everyone is weaker than either password it sat in front of
  • Session hardeningsigned 30-day httpOnly cookie — today's session dies with the 1-hour Supabase token, which is why you keep getting logged out
  • Rate limit5 attempts / 15 min per IP on /api/auth/login — brute force is the only new surface, so cap it

Dashboard — de-chunked HAIRLINES, NOT BOXES

Same data, half the ink. The six bordered stat cards collapse into one stat strip (single surface, hairline column dividers — the app's stats pattern). Lists lose their per-row boxes and iOS-blue/green accent circles; rows sit on 0.5px hairlines with the app palette only: gold for accent, flame for warnings, warm gray for everything else. Lesson titles go serif — content reads, chrome labels.

Why this reads better

  • One surface, not sixthe stat strip is scanned left-to-right as a sentence; six bordered cards are read as six separate widgets
  • Borders were the chunkevery current card carries border + fill + radius; the app never boxes rows — hairlines carry the structure
  • Palette disciplineiOS #007AFF / #34C759 / #FFCC00 leave; gold = accent, flame = warning, green only for deltas — same grammar as the app
  • Serif where it matterslesson and saint names in Playfair make the content pop out of the chrome, like the app's cards
  • Deltas add meaning"+6 this week" under Pro users answers the question you actually open the dashboard to ask

Weekly report — every Monday, both inboxes NEW · CRON + REPORTS TAB

Every Monday at 9:00 ET a Vercel cron computes the week's numbers, saves a snapshot, and emails it to both of you. The same report lives under Reports in the sidebar — with history — so nobody digs through screens to answer "how did the week go?". Trials and paying subs come from a new subscription_events table the Superwall webhook now writes on every store event; downloads come from download_clicks; users from users.

Plumbing

  • Event lognew subscription_events table — webhook inserts every Superwall event (product, period type, timestamp, raw payload)
  • Metrics fnadmin_report_metrics() Postgres function, service-role only
  • CronVercel cron → /api/reports/weekly Mondays 13:00 UTC · guarded by CRON_SECRET
  • EmailResend → both admin addresses · plain dark HTML matching this card
  • Snapshotevery run stored in admin_weekly_reports — the Reports tab reads history from it
  • Run nowsame endpoint, admin session instead of cron secret

Limits worth knowing

  • History starts nowevents log from deploy day forward — Superwall can't backfill
  • Trial ≠ payinga trial converts to "paying" at first real charge (the day-7 renewal), matching how the money actually moves
